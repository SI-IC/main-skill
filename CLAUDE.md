# main-skill — заметки для разработчика плагина

Для тех, кто правит сам плагин. **User-facing правила живут в `skills/workflow-rules/SKILL.md`** — здесь не дублируются.

Здесь только то, что не выводится из кода, тестов и хуков: процесс, карта синхронизации, осознанные компромиссы и известные дыры. Инвариант «почему именно так» ищи рядом с кодом — комментарием `Не менять, потому что …`. Устройство триггера — в его коде и в `hooks/**/*.test.js`; перечни паттернов, порогов и форматов сюда не копируй, они протухают молча.

## Что это за репо

Personal Claude Code плагин с workflow-правилами. Распространяется как marketplace (`.claude-plugin/marketplace.json`), ставится одной командой (README → Install).

SessionStart-хук подталкивает Claude вызвать `Skill: main-skill:workflow-rules` — содержимое приходит skill-каналом, без 10KB-капа на stdout хуков. Ядро правил — `SKILL.md`; условное и по-триггерное — `skills/workflow-rules/references/*.md`.

## Процесс правки

**Bump version при каждой правке.** Любая правка файла → инкремент `version` в `.claude-plugin/plugin.json` до коммита. Без bump-а `claude plugin update` не подтянет свежий контент из кеша.

**Тесты.** Node-сьюты запускаются напрямую, sh-хук отдельно:

```bash
for t in hooks/*.test.js hooks/lib/*.test.js; do node "$t" || break; done
sh -n hooks/session-start.sh && sh hooks/session-start.test.sh
```

Правка любого `hooks/**/*.js` без обновления парного `*.test.js` — нарушение Stop-триггера D.

**Стиль правил в SKILL.md / references.** Одно правило — заголовок + 1–3 строки, повелительное наклонение, без преамбул «почему это важно». Плагин работает только с моделями 5-го поколения, где переограничение вредит ([обоснование](https://claude.com/blog/the-new-rules-of-context-engineering-for-claude-5-generation-models)): без CAPS-нажима, без «списков не-делай», без повторов-для-надёжности. Правило = принцип + enforcement-ссылка; давление несёт хук, не тон текста. Каждый порог и список — в одном каноническом месте (пороги J/N и security-regex — `stop-triggers.md`), остальные ссылаются.

Исключение из краткости — машинопроверяемые форматы блоков (`<premortem>`, `<edge-cases>`, `<self-review>`, `<review-triage>`): шаблон показывай целиком, это спецификация валидатора.

Перед коммитом перечитай diff: для каждой добавленной секции > 5 строк выкинь треть.

**Размеры.** `SKILL.md`: кап 5000 токенов жёсткий только при компакции (после неё Claude Code перезагружает лишь первые 5000 токенов skill-а), основной пользователь до компакции не доходит — поэтому это ориентир. Функционал при этом инвариант: жми редактурой и выносом в `references/*.md`, не выкидывая правила. `CLAUDE.md`: кап 40 KB, гардится `claudemd-guard`.

## AgentTool-гейт моделей 5-го поколения

Сервер подмешивает gen-5-моделям в системный промпт «Do not call the AgentTool unless the user requested it» (кеш `.claude.json` → `clientDataCacheSlots`, tengu-флаг; локальная чистка бесполезна — пересинхронизируется, публичной ручки нет). Модель трактует «user requested» узко и пропускает ревью-сабагентов триггера J, делая ревью сама.

Контр-авторизация («запуск ревью-сабагентов = standing-запрос юзера, гейт снят своим же „unless“») продублирована в четырёх каналах:

1. `SKILL.md` §self-review;
2. `reasonJ` (howTo) в `verify-changes.js`;
3. `emit_skill_invocation` в `session-start.sh`;
4. строка в юзерском `~/.claude/CLAUDE.md` — самый авторитетный канал, её провижинит `ensure_standing_request` (идемпотентно, действует со 2-й сессии, opt-out `MAIN_SKILL_CLAUDEMD_PROVISION=0`).

Компромиссы провижининга: N гонящихся первых стартов дают до N−1 безвредных дублей; ручное удаление строки без opt-out перезаписывается; после деинсталляции плагина строка остаётся (README велит удалить руками); read-only HOME → тихий no-op, сессию страхует SessionStart-инструкция.

Потолок teeth: анти-луп-гард в `verify-changes.js` пропускает повторный Stop после одного блока — «слово юзеру» by design. Упорный отказ модели хуком не дожимается, решает юзерский канал.

Замер 2026-07-27 по транскриптам: правило «premortem-линза не на haiku» соблюдалось 10/12, два прогона Клод явно запустил на haiku вопреки SKILL.md — отсюда модельный гейт в J, текстом это не лечилось.

## Известные дыры и осознанные компромиссы

Все — в сторону молчания зуба (false negative), если не сказано иное. Ужесточение каждой стоит ложных блокировок, поэтому оставлены сознательно.

**Общее.** Хук видит факт, а не вердикт: `echo "curl localhost"` формально закрывает M, декоративный второй сабагент-вызов сбрасывает `edgeModel` в J. Всё, что внесено мимо Edit/Write (Bash heredoc, sed), счётчикам не видно. Файл, удалённый до Stop, снимает с себя D/E/F/A.

**Триггер D.** `__tests__/checkout.ts` без спек-суффикса import-scan-ом не читается: спека фиксирует только `*.spec.*` / `*.test.*`, иначе хелперы стали бы «доказательством». Алиас с другим родительским сегментом (`#models/db` → `app/auth/db.ts`) — FN. Импорт одноимённого npm-пакета — FP класса «импортирует, но не ассертит»: осознанно приемлем, иначе Claude выдавливается в широкие ignore-глобы.

**Триггер D, что намеренно НЕ скипается.** `config/`, `deploy/`, `scripts/`, `commands/`, `bin/` (кроме трёх Adonis-имён) и generic ops-имена (`run.sh`, `entrypoint.sh`) требуют парного теста. Основание — реальный инцидент: ace-команда `commands/korp_migrate.ts` в проекте ERP несла миграционную логику и уехала без теста. Проект глушит такие пути своим `MAIN_SKILL_VERIFY_IGNORE_GLOBS`, глобального исключения не будет.

**Триггер E.** Мутация в конвенции, не покрытой сигнатурами `hasMutatingHandler`, деградирует до D (парный тест любого слоя, возможно unit). Сужается добавлением сигнатур. Лишний endpoint-тест на некритичном роуте безвреден, e2e-пролиферация — нет.

**Триггер L.** Корпоративные прокси-registry (Verdaccio, Artifactory, JFrog) не ловятся как lookup — в таких проектах `MAIN_SKILL_VERIFY_DEPS=0` либо lookup через `npm view`. `[project.optional-dependencies]` в pyproject.toml не парсится. Docker SHA-pin пропускается намеренно.

**Триггер M.** Layout-oracle (клиппинг, наложение геометрией) хук не проверяет — к нему толкает `reasonM`, рецепт в `references/testing-strategy.md`.

**Триггер N.** Дельта-счётчик добавленных строк: `replace_all` считается один раз (множитель сайтов неизвестен без чтения файла); построчно совпадающее тело удалённого блока поглощает строки нового (rename одной из двух похожих функций); перенос блока двумя правками — наоборот FP (дельты пар не видят друг друга). Модельный гейт ловит только явный haiku в самом вызове: `CLAUDE_CODE_SUBAGENT_MODEL`, организационный allowlist и `model` во frontmatter кастомного сабагента хуку не видны; haiku-сессия целиком по бюджету не ловится структурно — иначе ложный блок именно у бюджетного юзера.

Анти-generic фильтр гипотез — floor, не потолок: «сеть упадёт → … → добавить ретраи» проходит по термину механизма. Цель зуба — чтобы ритуал состоялся; качество несут SKILL.md §2 и `reasonN`.

**Гарды.** Все PreToolUse-гарды обрываются на payload > 1MB (`aborted` → exit 0) и правку тогда пропускают: одна огромная правка обходит их целиком. `claudemd-guard` не ловит «тысячу мелких правок» — метрика на одну операцию. `ignore-glob-guard`: carrier-список фиксирован, `VAR` в `docker-compose.yml` / `Makefile` / `.github/workflows/*.yml` не гардится. `comment-guard`: `/** */` с тегом — легальный обход для прозы (цена за то, что JSDoc остаётся API-документацией); перенос комментария двумя правками читается как добавление; распознавание regex-литерала против деления — эвристика по предыдущему токену, экзотика мис-парсится (гард тогда fail-toward-deny, снимается `MAIN_SKILL_COMMENT_CHECK=0`). Тест-именованные `*.sh` из гарда исключены целиком: там комментарий-заголовок кейса — это имя теста, его читает `validateEdgeCases`. HTML-комментарии в `<template>` у `.vue/.svelte/.astro` сканеру не видны вовсе — открытый канал и для гарда, и для контент-детекторов D/M (дыра досталась по наследству от `stripBlockComments`).

**Per-session disable.** Сентинел `~/.claude/plugins/.main-skill-off` глобальный (user-level), не привязан к `session_id` → пока активен, задевает параллельные окна Claude Code. Для одно-оконного потока корректно.

**plugin-check.** Читается только user-level `~/.claude/settings.json`; плагин, включённый через project-level `.claude/settings.json`, ложно попадёт в «не установлен». Минор — `enabledPlugins` хранится на user-level.

## Дог-фудинг: грабли при работе НАД этим репо

- Валидные `<premortem>`-блоки из тестовых фикстур эхо-ятся в тексты сессии и закрывают триггер N сами. Примеры в `reasonN` и `premortem.md` поэтому закомментированы `#`.
- Фикстуру с широким ignore-глобом нельзя создать через Bash — её поймает `ignore-glob-guard`. Пиши такие фикстуры через `fs.writeFileSync`, для ручной проверки CLI — node-скриптом с разбитым именем переменной.
- Правки в `/tmp` (разведочные скрипты) мехчеки не триггерят — так и задумано.

## Валидации, на которых стоят решения

- **Премортем-линза** (2026-07-16, синтетика Telegram 4096 + Stripe webhook): промпт вытаскивает 4096 / parse_mode / retry_after / идемпотентность / zero-decimal и на haiku, и на sonnet; sonnet специфичнее (цитаты доков через WebFetch). На изолированном 50-строчном файле контрольный code-review ловит те же критикалы — ценность линзы в концентрации без minor-шума; в реальных больших диффах ревью 4096 пропускал.
- **Экономика ревью-сабагентов** (2026-07-27): брифинг с диффом в промпте отвергнут — промпт умножается на число агентов, экономии при неизменном качестве нет.
