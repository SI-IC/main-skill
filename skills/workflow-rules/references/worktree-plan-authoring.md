# Авторинг плана под worktree-skill

Когда план не влезает в одну сессию И его фазы можно сделать **параллельными** — оформи его так,
чтобы плагин **worktree-skill** исполнял фазы одновременно (каждую в своей git-worktree), а затем
серилизованно вливал в базовую ветку с авто-резолвом конфликтов по контрактам. Цель: **ускорить**
реализацию при **минимизации конфликтов**, сохранив все обязательные требования workflow-rules.

Это параллельный аналог circle-skill. Общий формат маркеров/преамбулы/журнала — как в
`circle-plan-authoring.md`; здесь только отличия параллельного плана. Читай оба.

Перед записью прогони полный Alignment (фаза 2 workflow-rules) по ВСЕМУ плану сразу — в фоновых
сессиях спросить нельзя.

## Когда worktree, а не circle

- **worktree** — когда фазы удаётся сделать **независимыми** (разные файловые поддеревья/домены),
  так что они идут параллельно почти без пересечений. Выигрыш — время.
- **circle** — когда фазы жёстко последовательны (каждая строится на предыдущей), пересечений много
  и контрактами их не убрать, либо нужна простая пошаговая отладка. Выигрыш — простота, минимум
  конфликтов.
- Требования worktree: проект — git-репо, есть базовая ветка (`dev`), рабочее дерево чистое.

## Формат — отличия от circle

Маркер — `worktree:` (не `circle:`):

```
## Фаза 2 — API-слой
<!-- worktree: status=pending order=20 deps=[1] autonomy=auto obstacle="" -->
```

Поля те же. **Важно про `deps`:** зависимость удовлетворяется только когда фаза **влита** в базу.
`deps` задаёт **границу волны** — фаза с `deps=[1]` стартует лишь после того, как фаза 1 влита.
Поэтому `deps` ставь ТОЛЬКО на жёсткие зависимости (см. ниже); лишний dep убивает параллелизм.

Добавь в преамбулу (до первой фазы — попадает в срез каждой фазы и в merge-сессию):

- **`## Контракты`** — общие интерфейсы для пересекающихся фаз. Это ядро параллельного плана:
  - **сигнатуры** функций/методов/типов, которые одна фаза отдаёт, а другие потребляют;
  - **форматы данных** (схемы событий, DTO, API-контракты);
  - **владение файлами** — какой файл единолично правит какая фаза; остальные его не трогают;
  - **соглашения** об именах/путях/ключах.
    Merge-сессия разрешает конфликты СТРОГО по этой секции — что здесь не зафиксировано, там она
    вынуждена гадать и, скорее, отдаст `blocked`.
- **`<!-- worktree-verify: <cmd> -->`** — команда интеграционного verify-гейта после каждого мержа
  (сборка/тесты/линт — исполняемый смоук, а не только type-check). Без неё база не проверяется —
  задавай всегда, если проект её имеет.

## Декомпозиция под независимость — главный навык

Метрика — **непересекающиеся файловые поддеревья / зоны владения**, не LOC. Две фазы независимы,
если множества файлов, которые они правят, не пересекаются.

1. **Режь план по владению файлами/модулями**, а не по слоям-времени. Фаза = «эти файлы мои».
2. **Пересечения неизбежны → выведи их в контракт**, а не в жёсткую зависимость. Пример: фаза A и
   фаза B обе трогают `types.ts`. Плохо — сделать B зависимой от A (потеря параллелизма). Хорошо —
   в `## Контракты` зафиксировать точные типы; A и B идут параллельно, каждая добавляет своё по
   контракту, merge-сессия сводит.
3. **Жёсткая зависимость (тип «B физически строится на артефакте A»)** оставляй только когда её
   нельзя убрать контрактом (B не может даже начаться без файлов A: миграция поверх схемы, кодоген
   из сгенерированного A артефакта). Тогда `deps=[A]` — это осознанная **граница волны**. Минимизируй
   число таких границ: в идеале волна одна.
4. **Файл-владелец на фазу.** Если один файл правят несколько фаз — либо назначь единственного
   владельца (остальные обращаются через его интерфейс из контракта), либо чётко подели файл на
   секции с владельцами. Общий «свалочный» файл, который все дописывают — источник конфликтов №1.

## Тело фазы — как в circle + «Контракт для пересечений»

Всё из `circle-plan-authoring.md` (выбранный подход + отвергнутая альтернатива, файловый манифест,
шаги, edge-cases, verify-гейт = исполняемый смоук, pre-authorized default+fallback вместо вопросов).
Плюс обязательно:

- **Строка «Контракт для пересечений»** — что именно эта фаза обязана держать, чтобы не конфликтовать
  с соседями: какие файлы её (правит только она), какие чужие она НЕ трогает, какой публичный
  интерфейс отдаёт downstream-фазам (со ссылкой на `## Контракты`).
- **Файловый манифест — источник границ владения.** Именно по нему проверяется независимость: если
  манифесты двух фаз одной волны пересекаются по путям без записи в контракте — это будущий конфликт,
  переразбей или допиши контракт.

`autonomy=needs-human` — только на необратимое/прод-риск (как в circle). Разведку кодовой базы делай
раз при планировании: карта в преамбулу + файловый манифест в тело фазы.

## Handoff

После записи файла:

1. **Самопроверка валидности** (до показа): маркеры `worktree:` в пределах 5 строк под заголовком;
   `order` возрастает; каждый `deps`-id ссылается на существующую фазу и не на `needs-human`/`skipped`;
   есть `## Контракты` (если фазы пересекаются) и `<!-- worktree-verify: -->`; `## Журнал` присутствует.
2. **Проверка независимости:** сопоставь файловые манифесты фаз каждой волны (одинаковый набор
   влитых deps = одна волна). Пересечения путей без покрытия контрактом — почини (переразбей или
   допиши контракт) до показа.
3. Покажи разбивку (фазы + домены + волны + порядок).
4. Выдай точную команду запуска: `/worktree-skill docs/superpowers/plans/<файл>.md`.
5. Не запускай worktree сам — это user-invoked команда.
