**Запуск только по явному запросу.** Эта команда выполняется, лишь когда пользователь сам её вызвал (`/main-skill:check-ignore-globs`) или прямо попросил проверить/сузить ignore-глобы. Если ты рассматриваешь запуск по своей инициативе (увидел широкий глоб по ходу другой задачи) — НЕ запускай: максимум одной строкой упомяни, что есть такая команда, и продолжай текущую задачу.

Проверяю, нет ли в этом проекте ШИРОКИХ `MAIN_SKILL_VERIFY_IGNORE_GLOBS` — каталог/язык-глобов (`src/**`, `**/*.ts`, `config/*`), которые глушат Stop-триггер D (проверку парного теста) сразу по целой папке, пряча заодно и реальную непокрытую логику. PreToolUse-гард блокирует запись таких глобов сейчас, но глобы, заданные ДО его появления, остаются — эта команда их находит.

## 1. Запусти аудит

Найди audit-скрипт плагина и выполни против текущего проекта:

```bash
SCRIPT="${CLAUDE_PLUGIN_ROOT:-}/hooks/lib/audit-ignore-globs.js"
[ -f "$SCRIPT" ] || SCRIPT="$(find "$HOME/.claude/plugins" -type f -path '*main-skill*/hooks/lib/audit-ignore-globs.js' 2>/dev/null | sort -V | tail -n1)"
node "$SCRIPT" .
```

Скрипт сканирует carrier-файлы проекта (`.env*`, `.claude/settings*.json`, `.mcp.json`, `*.sh`), home-конфиги (`~/.claude/settings.json`, shell-rc) и текущее окружение; каждый глоб классифицирует узкий/широкий через ту же `isBroadIgnoreGlob`, что и гард, — расхождения между командой и гардом быть не может.

## 2. Разбери широкие

Широких нет → сообщи «широких ignore-глобов нет» и заверши.

Для каждого широкого глоба:

1. Посмотри, что реально лежит в покрытой им папке (`ls` / Glob). Отдели нетестируемое (генерируемое, конфиги, `*.d.ts`, `*.pb.go`, миграции — многое из этого и так авто-скипается триггером D) от файлов с логикой, которым тест нужен.
2. Предложи замену:
   - сузить до имени/расширения нетестируемых файлов: `dir/**/*.gen.ts`, `src/generated/schema.ts`, `dir/*.pb.go`;
   - папка целиком генерируемая и её паттерны уже авто-скипаются → глоб, возможно, вообще не нужен — убери;
   - весь репо на централизованных тестах (`tests/` отдельно, рядом с src тестов нет) → это НЕ про глоб: предложи `MAIN_SKILL_VERIFY_CHANGES=0` на проект вместо глоба на всю папку.
3. Не угадывай, какие файлы «не нужны» — сверься с содержимым папки; при неоднозначности спроси пользователя.

## 3. Применить

Спроси подтверждение и внеси сужение в тот же источник, где глоб задан (файл из отчёта — home-источники `~/...` действуют на все проекты, правь их осознанно). После правки перезапусти скрипт из шага 1: в отчёте не должно остаться широких глобов, кроме осознанно оставленных пользователем (тогда напомни про `MAIN_SKILL_IGNORE_GLOB_CHECK=0`).

Язык — русский. Ничего не меняй без подтверждения пользователя.
