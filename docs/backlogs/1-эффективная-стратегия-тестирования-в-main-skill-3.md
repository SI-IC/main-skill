## Цель (реальная, широкая)

Доработать плагин `main-skill` так, чтобы **проекты, использующие его, применяли наиболее эффективную стратегию тестирования** — по ТРЁМ осям одновременно:

1. **Корректность / edge** — код работоспособен, соответствует задаче юзера, покрывает edge cases.
2. **Right-amount** — НЕ under- и НЕ over-testing (не тестировать тривиальное/генераты/невозможное — видео, пиксели canvas, шрифты).
3. **Скорость** — прогон тестов максимально быстрый, «не по полчаса перед деплоем».

ВАЖНО: фронт-визуал («Claude сказал готово, а в UI сломано») — это ОДИН ИЗ примеров/фасетов, а НЕ главная цель. Прошлая сессия ошибочно сузилась до него и выдала часть за целое — не повторять этот дрейф. Все три оси должны быть покрыты.

## Что уже есть в плагине (не дублировать)

Stop-хук `hooks/verify-changes.js` с триггерами A–L (`references/stop-triggers.md`):
- A (нет verify), D (src↔парный unit-тест), E (controller/route→e2e), F (edge-cases декларация), G (lint), H (docs), J/K (self-review+триаж), L (dep version-lookup).
- Skip-логика для D в `hooks/lib/checks.js` (`SKIP_PATH_PATTERNS`/`SKIP_FILENAME_PATTERNS`/`isPresentationalSFC`/`isTypeOnlyTsFile`).
- SKILL.md: разделы «Tiered test strategy» и «Reproduce-before-done» (это уже guidance про скорость и фронт — НЕ переписывать, ссылаться/расширять).

Соседний плагин `superpowers`: TDD (test-first/red-green/моки только если неизбежно), verification-before-completion (evidence before claims), testing-anti-patterns (не тестируй мок/пустышку). НЕ дублировать — ссылаться.

## Задачи по осям

### Ось СКОРОСТИ (главный пробел — сейчас механизма нет)
- **Рефайн триггера E** (`checks.js:isControllerOrRoute`/`findE2eFile`, `verify-changes.js` E-блок): сейчас E требует e2e на КАЖДЫЙ controller/route → раздувает suite (e2e-пролиферация = причина №1 получасовых прогонов) и провоцирует over-testing. Ослабить: e2e обязателен только для КРИТИЧНЫХ endpoint, для CRUD достаточно integration.
  - CAVEAT (критично, подтверждено ревью): детектить критичность по **HTTP-методу / мутирующему эффекту**, НЕ по regex имени пути. Иначе неназванные мутации (`/transfer`, `/withdraw`, `/users/:id/delete`) легально минуют e2e — дыра в E. Именно из-за этой дыры рефайн E в прошлой сессии был отложен как небезопасный в наивном виде.
- Рассмотреть лёгкий **неблокирующий advisory** на медленный suite (разовый, не Stop-блок): парсинг времени прогона хрупок — держать как guidance/совет, не как жёсткий триггер (Stop-хук видит только транскрипт, не тайминговую БД).
- Сделать «Tiered test strategy» из SKILL.md ощутимее: селекция в inner-loop (`vitest --changed`/`jest --findRelatedTests`/`pytest --testmon`), параллель+кэш в финале.

### Ось RIGHT-AMOUNT (анти-over-testing)
- Вынести **общий человекочитаемый stop-list «что НЕ тестировать»** (генераты, тривиальные getter/setter, DTO, конфиги, презентационные компоненты, ВИДЕО-воспроизведение, canvas/WebGL-пиксели, точный рендер шрифтов, сторонний код) — в reference, на который ссылается SKILL.md. Часть логики уже в `checks.js` (SKIP-паттерны) — свести, не плодить третий источник истины.
- НЕ строить отдельный триггер «осмысленный тест» (≥1 assert): в прошлой сессии оба субагента-ревьюера отвергли — YAGNI, парсер на 8-10 экосистем, массовые false-positives (table-driven/custom-matchers/RTL getByText/property-based/legit snapshot). Семантически это уже ловит self-review (J/K). Максимум — узкое расширение F, если реально нужно.

### Ось КОРРЕКТНОСТИ — backend layer-strategy (сейчас в плагине нет вообще)
- Добавить **таблицу выбора слоя** (unit/integration/e2e — когда обязателен, когда избыточен) в reference. Источник — анализ этой сессии: много логики/мало зависимостей→unit; стыки (код↔БД, service↔repo, handler↔логика)→integration; критичные сквозные пути→few e2e.
- Ключевое правило: **repository-слой тестировать против РЕАЛЬНОЙ БД (Testcontainers), не против моков и не против in-memory H2** — моки не ловят SQL-ошибки/constraint/FK/orphan/JSONB-квирки; H2≠прод. Гибрид: реальная БД только на repo-слой (немного тестов) + test-double репозитория в остальных.

### Ось КОРРЕКТНОСТИ — frontend-визуал (это ОДНА из задач, не главная)
Триггер, требующий РЕНДЕР-проверку на фронт-правку (unit в jsdom не рендерит — нет layout-движка, не ловит «не отрисовалось / текст за полем / окна внахлёст»). Прошлая сессия это реализовала и ОТКАТИЛА — переиспользовать как референс-дизайн:
- Новый триггер (напр. M): frontend-правка (`classify==='frontend'`, минус `isTestFile`/`isDocFile`) без render-проверки после последней фронт-правки → block. Render-класс = headless-браузер / `curl|wget` по **localhost** / active browser-MCP; НАМЕРЕННО без vitest/jest/pytest и без внешнего `https://`-curl. Вынести render-детект в общий `isRenderVerifyCmd` (переиспользовать в verify-ветке — не дублировать regex). Опт-аут отдельным env (напр. `MAIN_SKILL_VERIFY_RENDER=0`), НЕ переиспользуя `MAIN_SKILL_VERIFY_FRONTEND` (тот уже legacy-алиас `_CHANGES=0` = весь хук).
- Исключать не-рендерящееся: type-only `.tsx/.jsx`, token-only CSS (только `--custom-props`), `@generated`. Презентационный SFC НЕ исключать — визуал именно там. Fail toward требования на нечитаемом файле.
- **layout-oracle** как рецепт в reference (не как принудительный артефакт → иначе over-testing): в headless-браузере обойти элементы, свалить если `el.scrollWidth > el.clientWidth` (клиппинг) или bounding-box'ы сиблингов пересекаются (наложение). Это машинно ловит overflow/overlap детерминированно (геометрия, не пиксели), не хрупко кросс-платформенно, без baseline. pixel-visual-regression — последнее средство.

## Известные грабли из прошлой сессии (не наступать снова)
- **ReDoS в стрипе комментариев:** любой regex для `/* */` (и наивный lazy, и «unrolled»-альтернация с вложенными квантификаторами) квадратичен/экспоненциален на adversarial-входе из множества незакрытых `/*` (200KB → секунды/десятки секунд, вешает Stop-хук). Использовать **посимвольный однопроходный сканер** (гарантированно O(n)). Репо уже документирует прошлый ReDoS в SFC-сигналах.
- `lastFrontendEditIdx` (или аналог) должен исключать тест-файлы, иначе правка `Card.test.tsx` после рендера сдвигает индекс и триггер ложно бьёт повторно на неизменённый компонент.
- Хук видит только ФАКТ (рендер был / скриншот снят), НЕ вердикт «выглядит правильно» — самооценку скриншота подделать нельзя, в зубы её не класть. Осознанный потолок: teeth требуют реальный рендер + толкают к layout-oracle через guidance.
