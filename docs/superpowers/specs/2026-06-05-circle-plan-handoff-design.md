# circle-plan handoff — дизайн

**Дата:** 2026-06-05
**Статус:** approved, к имплементации

## Проблема

В сессии с main-skill (workflow-rules) иногда рождается план, который заведомо не влезает
в одну сессию (много доменов / большой объём). Хочется, чтобы такой план автоматически
оформлялся под исполнение плагином **circle-skill** (по фазе на отдельную фоновую сессию):

1. **Формат** — соответствует контракту circle-skill.
2. **Самодостаточность** — все узкие места, требующие согласования с пользователем, проработаны
   в планирующей сессии; при имплементации Claude занимается только кодом, не согласованием.
3. **Размер фаз** — сгруппированы по доменам и объёму так, чтобы каждая фаза комфортно шла в
   отдельной сессии: контекст ~30% (max 40%), но фазы не настолько мелкие, чтобы тратить время
   на инициализацию лишних сессий.

## Контракт circle-skill (источник истины — его репо)

- Фазы: заголовок `## Фаза <id> — <title>` (`<id>` — `\S+`, разделитель `—` или `-`).
- Маркер в пределах 5 строк под заголовком:
  `<!-- circle: status=pending order=20 deps=[1] autonomy=auto obstacle="" -->`.
- Поля: `status` (`pending|in_progress|done|blocked|skipped`), `order` (int, ключ сортировки),
  `deps` (id предшественников, удовлетворяются ТОЛЬКО статусом `done`), `autonomy` (`auto|needs-human`),
  `obstacle`.
- Append-only секция `## Журнал` (записи фаз — уровня `###`, остаются внутри секции). Executor
  читает журнал предыдущих фаз на старте (`circle_plan.py journal`).
- Executor дополнительно читает «секции контекста, стратегии и рисков плана».
- `needs-human` фазы исключаются из автономного цикла (владелец подтверждает на препролёте).
- Executor сам дробит фазу на подфазы `2a/2b`, если она не лезет в сессию (рантайм-страховка размера).
- Verify-гейт фазы — это МИНИМУМ: executor-prompt прямо требует исполняемый смоук, а не type-check,
  если фаза производит инфру/контракт для следующих.

## Решения (из brainstorming)

- **Триггер:** авто-детект + предложение. В конце планирующего флоу, если план многодоменный /
  оценочно > одной сессии — Claude предлагает оформить как circle-план; решение за пользователем.
  Не авто-без-спроса, не только-по-явной-просьбе.
- **Самодостаточность:** pre-authorized default + fallback. В планирующей сессии выжимаем максимум
  решений из пользователя вопросами. Что объективно неизвестно до имплементации → в фазу пишется
  явный default-выбор + условие fallback, чтобы executor шёл без пользователя. `needs-human` —
  ТОЛЬКО для необратимого / прод-риска.
- **Размер (домен vs объём):** домен-первичен + склейка смежных. Домен ведёт границы и порядок;
  огромный домен режется на `2a/2b`; несколько смежных по зависимости/слою мелких доменов можно
  слить в одну фазу, если вместе они в бюджете и логически связаны. Метрика контекста — число
  различных ментальных моделей / файловых поддеревьев, не LOC.

## Форма поставки: reference-дока + триггер в SKILL.md (без кода)

Отвергнуты:

- **Скрипт-оценщик размера** (LOC→контекст% — слабый прокси, хрупко, тянет тесты; у circle уже есть
  рантайм-самодробление как страховка).
- **Хук/команда с авто-генерацией** (механический детект «план большой» ненадёжен; авто-запись файлов
  пользователь отверг, выбрав «предложение»).

Выбрано — guidance, ровно как вся архитектура main-skill (SKILL.md + conditional references, без рантайма).

### Артефакты

1. **`skills/workflow-rules/SKILL.md`** — короткая секция-триггер (~6 строк): в конце планирующего флоу
   при многодоменном / >1-сессионном плане предложить circle-формат; дальше — по reference; выдать
   команду `/circle-skill <path>`.

2. **`skills/workflow-rules/references/circle-plan-authoring.md`** — контракт авторинга:
   - Формат: маркеры, заголовки, преамбула «Контекст / Стратегия / Риски», пустой `## Журнал`.
   - Самодостаточность per-фаза: выбранный подход + отвергнутая альтернатива + обоснование; edge-cases;
     verify-гейт = исполняемый смоук; pre-authorized default + fallback; `needs-human` только для
     необратимого/прод-риска.
   - Сайзинг: домен-первичен + склейка смежных; цель ~30% (max 40%); оценка по ментальным моделям;
     огромный домен → `2a/2b`; не делать тривиально мелких фаз; страховка — самодробление circle.
   - deps/order: из доменного графа; order шагами по 10; deps = id предшественников.
   - Контракты между фазами: фаза, производящая инфру/контракт для следующих, описывает контракт +
     заметку «следующий шаг» для журнала.
   - Handoff: план в `docs/superpowers/plans/YYYY-MM-DD-<topic>.md`; выдать команду `/circle-skill <path>`.

3. **`.claude-plugin/plugin.json`** — bump version (обязателен на каждую правку репо).

### Инварианты

- SKILL.md остаётся под 5000 токенов (тяжёлый контент — в reference).
- Reference — конкретный, без преамбул «почему это важно»; формат — повелительные глаголы.
- Никакого кода/хуков/скриптов → новых тестов триггер D не требует (нет `*.js` правок).

## Верификация

- `node hooks/verify-changes.test.js`, `node hooks/lib/checks.test.js` и пр. остаются зелёными
  (контентные правки md не трогают код, но прогон подтверждает отсутствие регрессии).
- Smoke handoff-контракта: сгенерировать минимальный план по reference, скормить
  `circle_plan.py summary/next/journal` из репо circle-skill → парсится без ошибок, `next` выбирает
  первую фазу, маркеры валидны. Это доказывает, что наш формат реально совместим с парсером circle.
